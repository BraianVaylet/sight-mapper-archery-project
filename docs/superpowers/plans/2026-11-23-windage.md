# F3-D Deriva por marca — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Each sight gets a horizontal scale (`windageScale`), each mark an optional windage (`windageMm`), and the sight screen a second, horizontal ruler. The archer can always go back to the real windage after a wind correction.

**Architecture:** `windageScale` has the same shape as `SightScale`, with direction `right | left`. One pure helper in `domain` maps it to a regular `SightScale` (`right→down`, `left→up`), so conversion, formatting, bounds and the ruler are reused as they are. The calculator's rescale port gains an `axis` parameter (`vertical | windage`), which equipment calls once per changed scale.

**Tech Stack:** TypeScript strict, Zod 4, Hono + Mongoose 8, React 19 + TanStack, Vitest, Testing Library, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-23-windage-design.md` (read it first).

## Global Constraints

- Canonical units (ADR-005): windage is persisted as `windageMm` (mm). Conversion to readings happens only at the presentation edge.
- Windage is **never estimated**. Only measured marks with `windageMm != null` show it. No change to the model, the Doctor or the intermediate distances.
- API: `windageScale: SightScale | null` (optional on create; once set, it cannot go back to `null` on update). The PWA form requires it for a new sight and prefills it with a copy of the vertical scale (`direction: 'right'`).
- `windageMm: number | null`, optional on create and on PATCH (`null` clears it).
- New errors: `SM-MARK-422-003` `errors.mark.noWindageScale` (no params) and `SM-MARK-422-004` `errors.mark.windageOutOfScale` (`minMm`, `maxMm`). Declare them in `docs/errors.md`, then regenerate (`pnpm --filter @sight-mapper/types generate`).
- Export: `EXPORT_SCHEMA_VERSION = 3`. The rows already carry every field.
- Code and commits in English; docs in es-AR without accents; UI strings only through the ES+EN catalogs.
- Commit scopes allowed by commitlint: `repo, docs, domain, schemas, types, i18n, ui, client, api, pwa, account, equipment, calculator, ci, infra, e2e`.
- DoD: ES/EN, dark/light, 360/768/1440, accessible, OpenAPI, entry in `docs/BITACORA.md`.

## Review Focus

1. A sight with no `windageScale`: a PATCH or create with `windageMm` → 422 `SM-MARK-422-003`. The sheet shows no windage field, only a link to edit the sight. (Task 5, Task 8)
2. Changing only the vertical scale must not touch `windageMm`. Changing only `windageScale` must not touch `scaleValueMm`. Marks with `windageMm: null` never count as outside and are never rescaled. (Task 5)
3. Editing a mark to clear its windage stores `null`. Undo restores the previous value, `null` included. The replace dialog (409) carries `windageMm`. (Task 8)
4. `windageScale.direction: 'left'` draws `min` on the right end of the horizontal ruler. (Task 2, Task 7)
5. In ES, windage is typed with a comma (`2,5`), just like the reading, and is rounded to the windage scale's resolution, not the vertical one. (Task 8)
